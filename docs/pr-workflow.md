# PR 준비와 리뷰

개인 스킬의 유무와 관계없이 이 절차를 따라요.
실행 명령과 UI 확인 항목은 [AGENTS.md의 실행과 검증](../AGENTS.md#실행과-검증),
[UI 변경 시 주의점](../AGENTS.md#ui-변경-시-주의점)을 확인해요.

## 작성자

1. 구현 후 브랜치 범위에서 외부 동작을 유지하며 리팩토링해요. 정리할 코드가 없으면 생략하고 이유를 남겨요.
2. 변경한 동작을 직접 실행·검증해요.
3. 자체 코드 리뷰를 진행해요. 자체 리뷰에는 미커밋 변경도 포함할 수 있어요.
4. 필요한 수정을 하고, 영향받는 검증과 리뷰를 다시 수행해요.
5. 확정된 변경으로 changeset을 작성·확인하거나 생략 사유를 정리해요.
   대상·작성법·검사 명령은 [릴리스 워크플로](release-workflow.md#changeset-작성)를 따라요.
6. 최종 diff와 실제 검증 결과를 기준으로 PR 제목·본문을 작성해요.
   [공유 스킬](ai-skills.md#pr-제목과-본문-작성)을 사용할 수 있어요.

## PR 제목과 라벨

`develop` 대상 PR은 제목 검사가 통과하면 제목 접두어에 맞는 라벨을 자동으로 추가해요.
PR 생성·수정·재오픈, 커밋 추가, 리뷰 준비 완료 시 실행돼요.

| 제목 접두어  | 라벨            |
| ------------ | --------------- |
| `[FEATURE]`  | `feature`       |
| `[FIX]`      | `bug`           |
| `[REFACTOR]` | `refactoring`   |
| `[DOCS]`     | `documentation` |
| `[CHORE]`    | `chore`         |

제목의 유형을 바꾸면 새 라벨을 기존 라벨과 함께 추가해요. 이전 유형 라벨의 제거는 작성자가 판단해요.
`good first issue`와 `question`은 필요할 때 수동으로 추가해요.
자동화는 워크플로가 기본 브랜치에 반영된 뒤 발생하는 PR 이벤트부터 적용돼요.

## 리뷰어

- 제출된 PR의 base/head SHA를 확인하고 해당 head를 직접 실행·검증한 뒤 코드 리뷰를 해요.
- PR에 포함된 커밋만 대상으로 하며, 리뷰어의 로컬 변경을 섞지 않아요.
  기존 작업과 대상이 다르면 별도 worktree를 사용해요.
- 검증·리뷰 후 코드가 바뀌면 영향받는 검증과 리뷰를 다시 확인해요.
- 최종 승인은 사람이 판단해요. 코드 리뷰·검증 요청만으로 원격 승인이나 게시를 하지 않아요.
- 읽기 전용 리뷰에서는 문서를 직접 고치지 않고, 변경으로 인해 갱신이 필요한 지침을 보고해요.

## 검증 결과 기록

다음 내용을 남겨요.

- 대상 HEAD SHA와 비교 기준
- 미커밋 변경 포함 여부와 포함한 변경 목록
- 실행 명령·결과, 실행하지 못한 명령과 원인
- 화면 재현 절차와 미확인 항목

이전 실행이나 CI 결과를 직접 실행한 결과로 쓰지 않아요.
다른 커밋이나 작업 트리에서 얻은 결과는 구분하고, PR 제목·본문은 최종 변경에 맞춰 작성해요.
