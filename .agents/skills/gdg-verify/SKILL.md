# 브랜치와 PR 실행 검증

작성자와 리뷰어가 같은 절차로 변경을 실행하고, 확인한 대상과 결과를 재현 가능하게 남겨요.
제품 코드와 운영 데이터는 수정하지 않아요. 발견한 결함은 재현 절차로 보고해요.
문서 경로는 저장소 루트 기준이에요.

## 검증 대상과 환경

- 루트와 대상 경로의 `AGENTS.md`, README, 실제 `package.json`의 명령을 확인해요.
  `git status --short`, 현재 브랜치와 HEAD SHA를 기록하고 기존 작업을 보존해요.
- 작성자의 브랜치 검증은 사용자 지정, 확인 가능한 PR 대상, `develop` 순으로 기준을 정해요.
  `git merge-base HEAD <comparison-ref>`부터의 변경과 관련 호출부를 확인해요.
  기본적으로 미커밋·미추적 변경도 포함하고, 포함 여부와 변경 파일 목록을 기록해요.
  커밋된 변경만 요청했는데 작업 트리가 다르면 해당 SHA의 별도 환경에서 검증해요.
- 제출된 PR은 실제 대상 저장소와 base/head SHA를 확인해요. 로컬 브랜치 이름만으로 PR head와
  같다고 판단하지 않아요. PR 변경 범위는 `git merge-base <base-sha> <head-sha>`부터 head까지예요.
- 리뷰어의 실행 환경은 PR head와 일치해야 해요. 현재 작업 트리가 해당 SHA와 같고 깨끗하면
  사용하고, 그렇지 않으면 `git worktree add --detach <new-path> <head-sha>`로 별도 환경을 준비해요.
  필요한 ref를 가져와도 기존 브랜치를 강제로 덮어쓰거나 checkout·stash·reset으로 작업을 치우지 않아요.
  PR 정보를 확인할 수 없으면 필요한 ref나 SHA를 요청하고 추측한 브랜치를 검증하지 않아요.
- 별도 환경을 준비했으면 그 대상 SHA의 `AGENTS.md`, README와 패키지 설정을 다시 확인해요.
  원래 작업 트리의 명령·설정을 다른 PR 커밋에 그대로 적용하지 않아요.
- 설치가 필요하면 검증 환경에서 저장소가 지정한 런타임과 패키지 매니저, lockfile을 사용해요.
  시작·종료 시 diff를 확인하고, 생성물과 사전 변경을 구분해요. 직접 만든 서버만 종료하고,
  임시 worktree는 변경·산출물을 확인한 뒤 안전하게 정리하거나 남긴 위치를 보고해요.
  강제 삭제로 결과나 기존 작업을 버리지 않아요.

## 실행할 확인

- `AGENTS.md`의 코드·문서 변경별 검증을 적용해요. 설치된 테스트와 명령은 현재 설정에서
  확인하고, 없는 테스트를 실행했다고 쓰지 않아요. 로컬 검증에 배포·원격 동기화를 포함하지 않아요.
- UI 변경은 dev 서버를 실행해 변경한 화면과 영향받는 동작을 직접 확인해요.
  모집 상태·탭·모달, 로딩·오류·빈 결과, 키보드 동작과 반응형 검증 범위는 `AGENTS.md`와
  `docs/landing-spec.md`에서 확인해요. 명세의 개선 제안과 운영·디자인 미확정을 확정 정책으로 쓰지 않아요.
- 공유 패키지 변경은 공개 API와 실제 소비 앱을 함께 확인해요. JSON·날짜 변경은 소비 경로와
  관련 경계를 확인하고, 필요한 장애·빈 상태는 로컬에서 재현해요. 운영 데이터는 바꾸지 않아요.
- 브라우저·도구가 없거나 상태를 재현할 수 없으면 미확인으로 남겨요. 빌드 통과나 정적 코드
  확인을 실제 화면 검증 통과로 대체하지 않아요. 기존 CI 결과는 별도 근거로 표시해요.
- 릴리스 도구가 있는 대상에서는 `pnpm changeset:check`, `pnpm changeset status --verbose`를
  실행해 결과를 기록해요. 릴리스 도구·워크플로 변경은 `pnpm test:release`도 실행해요.
  명령의 존재는 대상 SHA의 package.json으로 확인하고, 검사 중 버전이나 changeset을 수정하지 않아요.

## 결과 전달

- 대상 base/head SHA 또는 로컬 HEAD SHA, 미커밋 포함 여부와 변경 목록, 실행 디렉터리를 적어요.
  미커밋을 포함한 결과는 해당 작업 트리 상태에 대한 결과임을 밝혀요.
- 실행한 명령·결과와 화면 재현의 입력·조작·기대 결과·실제 결과를 남겨요.
  실패한 검증, 실행 불가, 범위 밖 항목을 구분하고 필요한 환경·뷰포트·시간대도 적어요.
- 종료 전 검증 대상의 diff·작업 트리를 다시 확인해요. 검증 중 코드가 바뀌었거나 PR base/head가
  바뀌었으면 영향받는 확인을 다시 수행하고, 아직 확인하지 않은 결과를 최신으로 보고하지 않아요.
- PR 본문에 옮길 때는 `.github/pull_request_template.md`의 검증 항목에 맞춰 요약해요.
  별도 결과 파일은 요청받거나 저장소에 정해진 위치가 있을 때만 만들어요.
- 실행 검증 통과는 코드 리뷰나 승인을 대신하지 않아요. 리뷰어는 이 결과와 코드 리뷰를 근거로
  승인 여부를 직접 판단하며, 검증 요청만으로 원격 승인·댓글·PR 수정을 하지 않아요.
